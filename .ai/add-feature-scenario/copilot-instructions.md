# PnC Test Automation — Copilot Instructions

## Framework Overview
- **Language**: C# on .NET 8
- **Test Framework**: Reqnroll (Gherkin/BDD) + NUnit
- **Browser Automation**: Microsoft Playwright
- **DI Container**: Microsoft.Extensions.DependencyInjection
- **Project**: Insurance policy workflow automation (SFP, PA, BOP products)

## Dependency Injection Rules
- DI is configured in `Configuration/DependencyInjection.cs` with `[ScenarioDependencies]`
- Services are registered in `Startup.cs` → `ConfigureServices()`
- **Singletons**: BrowserFactory, TestContext, all Page objects, ApiHeaders
- **Scoped (per-scenario)**: NavigationService
- **Transient/InstancePerContext**: ScenarioContextData
- **HTTP**: Registered via `AddHttpClient<IApiService, ApiService>()`
- Every new page object MUST be registered in `Startup.cs` as a singleton

## Page Object Pattern
- All page objects inherit from `BasePage` in `Pages/BasePage.cs`
- Constructor signature: `public MyPage(IPage page) : base(page) {}`
- All methods must be `async Task` with `Async` suffix (e.g., `FillFirstNameAsync()`)
- Use Playwright locator methods: `GetByTestId()`, `GetByRole()`, `GetByText()`, `Locator()`
- Page objects live in `Pages/{ProductFolder}/{PageName}.cs`
  - SFP: `Pages/ExpertQuotePages/SFP/`
  - Express: `Pages/ExpressPages/`
  - ExpertService: `Pages/ExpertServicePages/`

## Step Definitions Pattern
- Classes decorated with `[Binding]`
- Dependencies injected via constructor (ScenarioContextData, page objects, services, configs)
- Methods decorated with `[Given]`, `[When]`, `[Then]`
- Table parameters are mapped using `TableMappingHelpers` static methods
- Step definition files live in `StepDefinitions/{ProductSteps}/`
  - Shared steps: `StepDefinitions/SharedSteps/`
  - SFP: `StepDefinitions/SFPSteps/`
  - PA: `StepDefinitions/PASteps/`
  - BOP: `StepDefinitions/BOPSteps/`

## ScenarioContextData
- The single data carrier for all test data across a scenario
- Located in `Helpers/ScenarioContextData.cs`
- Composed of domain models: `ClientData`, `AddressData`, `DriverData`, `VehicleData`, `PolicyData`, `PaymentData`, `AdditionalInterestData`, `PriorInsuranceData`, `BusinessData`, `FarmData`, `UnderwritingData`
- Access via: `_contextData.Client.FirstName`, `_contextData.Vehicle.Make`, etc.
- Legacy properties are backward-compatible delegates — do not remove them
- Retrieved from Reqnroll ScenarioContext: `ScenarioContext["ContextData"]`

## Gherkin / Feature Files
- Feature files live in `Features/{Product}/`
- Generated `.feature.cs` files are auto-generated by Reqnroll — never edit them
- Use `Background:` for shared setup steps within a feature
- Data tables use pipe syntax: `| Field | Value |`
- Token generators available in table values:
  - `{{firstName}}`, `{{lastName}}` — random names
  - `{{randomDOB}}` — random date of birth
  - `{{randomPhone}}` — random phone number
  - `{{randomEmail}}` — random email address
  - `{{randomSSN}}` — random SSN
- Tag scenarios with `@API` for API-only scenarios (skips browser launch)
- Tag with product tags for filtering: `@SFP`, `@PA`, `@BOP`

## Configuration
- `appsettings.json` is copied to output directory on build
- Config loaded via `ConfigurationBuilder` → `GetSection<T>()` for typed config classes
- Config classes in `Configuration/`: `CredentialsConfig`, `OAuthConfig`
- Never hardcode credentials — always inject via config

## Test Hooks & Lifecycle (`Hooks/TestHooks.cs`)
- `[BeforeTestRun]` — one-time setup
- `[BeforeScenario]` — browser launch (UI) or OAuth token (API)
- `[AfterStep]` — screenshot on failure
- `[AfterScenario]` — video + trace saved to `TestResults/{timestamp}/` on failure
- `[AfterTestRun]` — cleanup
- Traces and videos are only saved on failure
- Quote numbers are captured from URL or tab label and saved to `QuoteNumber.txt`

## API / HTTP Pattern
- `IApiService` / `ApiService` — injected HttpClient + ApiHeaders
- `ApiHelpers.SendPostRequestAsync()` — handles retry, token/cookie headers, HTML detection
- `AuthHelper` — supports PKCE, Password Grant, Client Credentials OAuth flows
- Bearer token in `Authorization` header

## DuckCreek Forms API (Important)
- Dual-user architecture: UI login user ≠ API service account user — this is by design
- HTTP 200 AND HTTP 500 are both valid responses — both contain forms XML
- HTTP 401/403 are the only true failures
- `Session.resumeRs status='failure'` in XML is EXPECTED — do not treat as an error
- Parse `printDoc` elements regardless of XML status attribute
- DuckCreek server: `{DuckCreekForms:ServerBaseUrl}/duckcreek/dctserver.aspx` (set via env var)

## Naming Conventions
- Classes: PascalCase
- Methods: PascalCase + `Async` suffix for async
- Properties: PascalCase
- Interfaces: `I` prefix (e.g., `IApiService`)
- Test data tokens: `{{camelCase}}`

## Forms Validation System

### Overview
End-of-policy forms validation verifies that DuckCreek attaches the correct mandatory forms to a policy. It runs as the **last step** in each scenario (e.g., `When user validates Forms via Duckcreek for state "<StateAbbv>"`).

### How It Works
1. **API call**: `FormsValidationService` POSTs to the DuckCreek forms API using `DuckCreekFormsClient`, parses the XML response, and builds a list of `ActualFormEntry` objects from `printDoc` elements.
2. **Baseline load**: `FormsValidationService.LoadExpectedFormsForLob(lob, state, testCase)` loads `Resources/ExpectedForms/{LOB}/{LOB}.json`.
3. **Validate**: Expected vs actual are compared. Results are written to an HTML report in `TestResults/{timestamp}/`.
4. **Test always continues** — forms failures are soft-asserts (reported but do not fail the scenario step).

### Baseline JSON Format (`Resources/ExpectedForms/SFP/SFP.json`)
Include-only format — forms not in the file are treated as "not expected":
```json
{
  "BASE":  { "SF00010120": ["AL","AR",...], "SF00020120": "all" },
  "BASIC": { "X32100925": ["IL"] },
  "CE":    { ... }
}
```
- **BASE**: forms loaded for ALL test cases (Basic Policy + Country Estate)
- **BASIC**: forms loaded only for Basic Policy test cases (in addition to BASE)
- **CE**: forms loaded only for Country Estate test cases (in addition to BASE)
- Value `"all"` = mandatory for every supported state
- Value `["AL","AR",...]` = mandatory only for listed states

### Section Mapping (How Sections Are Assigned by the Generator)
Excel sheet names map to JSON sections via `ExcelFormsParser.SheetToSection`:
| Excel Sheet | JSON Section |
|-------------|-------------|
| Division 0, Division 1 | BASE |
| Division 2–7, X-Forms | BASIC |
| T-Notices | BASE |
| Country Estate | CE |

### Regenerating the Baseline (Excel Masterlist → SFP.json)
Use the built-in `FormsBaselineGeneratorTool` (Category=Tools NUnit test):
```powershell
cd "c:\PnC Test Automation\PnC-TestAutomation"
dotnet test TestAutomation.csproj --filter "Category=Tools&Name~GenerateFormsBaseline" `
  -- 'TestRunParameters.Parameter(name="EXCEL",value="path\to\SFP Forms Masterlist v9.00.xlsx")' `
     'TestRunParameters.Parameter(name="LOB",value="SFP")' `
     'TestRunParameters.Parameter(name="COMMON_EXCEL",value="path\to\Common Forms MASTERLIST.xlsx")'
```
- Add `'TestRunParameters.Parameter(name="DRY_RUN",value="true")'` to preview changes without writing
- The diff is also saved to `TestResults/FormsBaseline/SFP_diff.txt`
- Both Excel files live in `Resources/ExpectedForms/SFP/`

### Excel Files Used
| File | Purpose |
|------|---------|
| `SFP Forms Masterlist v9.00 (1).xlsx` | SFP-specific forms — all divisions, X-Forms, T-Notices |
| `Common Forms MASTERLIST (all States) - Version 80.00 (2).xlsx` | Cross-LOB forms shared across product lines |

The parser (`ExcelFormsParser.cs`) auto-detects header rows by looking for 2-letter state abbreviations. State columns with `Y` = Mandatory (mapped to `YM`). Blank = Not Expected (omitted from baseline). The Common Forms file uses an LOB column lookup (column `SFP`) to find which state columns apply; common forms are merged into BASE and deduplicated against LOB-specific forms.

## What NOT to Do
- Do NOT use `[TestMethod]` — this is Reqnroll/NUnit, not MSTest
- Do NOT edit `.feature.cs` files — they are auto-generated
- Do NOT edit `SFP.json` by hand — regenerate it using the Excel masterlist tool above
- Do NOT hardcode credentials or environment URLs
- Do NOT make page objects transient — they must be singletons
- Do NOT skip registering new page objects in `Startup.cs`
